# Benchmark suite: what it times, the fit, the result files

Date: 2026-11-20. Status: accepted.

WP-16 fixes the parts of ADR-0010 that leave the benchmark open. Changes:

- **What is timed.** One call of `step!` on a `Simulation` with `NoForcing` and a random velocity (`random_velocity`, `E_kin = 0.5`) at `Δt = 1e-4`, `L = 2π`. The point is the median of repeated calls after 2 warm-up calls, each call followed by `KernelAbstractions.synchronize`. The number of repeats is `3 s / (time of one call)`, between 5 and 100. The time excludes forcing, diagnostics, checks and output; a real run adds them. The compressible model uses `Isothermal(cs = 10)`. The cost of a step does not depend on the parameter values.
- **Memory.** The memory of a point is the change of the used memory between before the grid exists and after the `Simulation` exists, after a full garbage collection. On CUDA it is the change of free device memory (this includes the cuFFT plan workspace); on the CPU it is the change of the Julia heap (this excludes the FFTW plans). The fit is `bytes = m·N² + c`.
- **Fit.** `t_step = a·N² log N + b·N² + c` with the natural logarithm. The least-squares system is weighted by `1/t_step`, so it minimises the relative error and the small grids count as much as the large ones. The residual is the maximum over the points of `|fit − t| / t`. The time of a step is not a smooth function of `N` for a FFT whose size has large prime factors; the benchmark uses powers of 2 only.
- **Configurations.** A configuration is `(model, scheme, integrating factor, device, T)`. The default set is both models with RK4 and the integrating factor on `cpu:Float64`, `cuda:Float64` and `cuda:Float32`, for `N = 256 … 4096`. Command-line arguments select the set (see `benchmark/run.jl`). A point that does not fit the device memory is dropped for that configuration only.
- **Result files.** `benchmark/results/<hostname>.toml` holds the machine description (`meta`) and one table per configuration under `config`: the points, the coefficients, the residuals. A run updates the configurations it measured and keeps the others. The files are committed, one per machine: they document the speed of the machines used and `predict.jl` runs from a clone. A result file is valid only for its machine (ADR-0010).
- **Prediction.** `benchmark/predict.jl` evaluates the fits for a target `(N, model, scheme, device, T, t_end, Δt)`. The walltime is `⌈t_end/Δt⌉` times the time per step. It warns when `N` lies outside the measured range.
- **CPU backend.** `benchmark/cpu_kernel.jl` times `propagate!` at `N = 2048` under the KernelAbstractions `CPU()` backend (POCL) and as a `Threads.@threads :static` loop, with 40 threads. The KA kernel takes 3.9 ms and the loop 5.6 ms, ratio 0.70. The KA backend is faster for this memory-bound kernel, so CompReS adds no separate CPU path.
- **Fit quality.** On the development machine the residual is 4.7% to 8.5% for four of the six default configurations and 15.2% (CPU, compressible) and 15.5% (CUDA Float32, incompressible) for two. A minimax fit does not reach 10% for these two. The three-term form misses the thread-overhead and cache transitions (BACKLOG, "Fit the time per step piecewise in `N`").
