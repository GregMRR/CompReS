## Findings
### E1 [blocker] The bit-for-bit restart test of WP-12 cannot pass, because a snapshot stores only physical-space fields
- Where: ROADMAP:158 (WP-12 acceptance); upstream claim at docs/adr/0009-output-netcdf-classes-registry.md:15.
- Evidence: ADR-0009:15 says "A snapshot holds the physical-space fields (`ux`, `uy` …) … and it is the only restart input. A restart reproduces the uninterrupted run bit for bit." The uninterrupted run keeps the spectral state û. The restart rebuilds it as truncate(rfft(irfft(û))), and this round trip is not the identity in floating point. `r1-E1.jl` (N = 16, Float64): "retained modes: 50  modes that differ bitwise after restart: 42  max |diff| = 1.96e-17 … bit-for-bit: NO".
- Consequence: the WP-12 agent cannot meet the acceptance test. It will either weaken the test without a recorded decision, or add a hidden round trip to the uninterrupted run. Either way the restart guarantee in ADR-0009 is false as stated.
- Hint: store the spectral state (or its exact bit pattern) in the snapshot as well, or replace "bit for bit" with a stated tolerance and record the choice in an ADR.
- Resolution: _(author)_

### E2 [major] No planned test exercises the integrating-factor stage algebra with a nonzero linear and nonlinear term together
- Where: ROADMAP:131-132 (WP-7); ADR-0011:11-12.
- Evidence: the only IF test is the Kolmogorov decay, where the nonlinear term is zero. The conservation test uses ν = 0, so the IF is the identity. The scalar-ODE order test at ROADMAP:132 does not say that it runs with the IF. `r1-E2.jl` applies a mutation to Lawson IF-RK4: every stage uses exp(LΔt) in place of exp(c_i LΔt). Output: Kolmogorov case error 2.2e-16 for both the correct and the mutated scheme; conservation case identical results; scalar ODE y' = −2y + y²: correct observed orders [4.6, 4.47, 4.32], mutant [0.9, 0.94, 0.97].
- Consequence: an IF bug that drops the scheme to first order passes every blocking test. Production runs use `integrating_factor = true` (ROADMAP:19).
- Hint: require the scalar-ODE order test for every scheme with the IF on, on an ODE with L ≠ 0 and N ≠ 0.
- Resolution: _(author)_

### E3 [blocker] The OU acceptance test of WP-9 does not test the injection normalisation
- Where: ROADMAP:143 ("OU mean injection within 5% of `ε` over a long sample with white-noise velocity"); ADR-0007:10.
- Evidence: `r1-E3.jl` (seed 7, M = 1e5 realisations, τ_f = 0.05, ε = 1). (a) An independent white-noise velocity gives ⟨u f⟩ = 0.0173, consistent with 0, not ε. (b) A velocity driven by the forcing, u' = −γu + f, gives σ²τ/(1+γτ): γ = 1 gives 0.961 ± 0.028 (theory 0.952); γ = 10 gives 0.665 ± 0.008 (theory 0.667). The injection depends on the response rate of the forced modes. The test as written has no stated response, no sample length and no confidence interval.
- Consequence: read literally, the test fails for any variance. Read as "the white-noise limit", it is undefined. The variance normalisation of a complex OU process per mode on the real-FFT half plane (a factor-2 trap, CLAUDE.md:39) then has no test that fails on a wrong factor.
- Hint: specify the test as u' = f (or u' = −γu + f with γτ_f ≪ 0.05), an ensemble mean with a seed, and a 95% interval around σ²τ_f summed over the support with the half-plane weights.
- Resolution: _(author)_

### E4 [major] The dependency graph omits edges that acceptance tests and interfaces need, and no WP owns the forcing term in the right-hand side
- Where: ROADMAP:70-75, 126, 132, 137, 168.

  - WP-8:137 requires "GLOBAL … defaults of ADR-0009", and these include "the injection … rates" (ADR-0009:21). WP-8 does not depend on WP-9 (ROADMAP:135).
  - WP-7:132 makes the conservation test blocking. That test measures E_kin and Z (ADR-0011:11), which WP-8 provides. WP-7 does not depend on WP-8 (ROADMAP:130).
  - WP-14:168 measures the "emitted `E_kin_comp`" after a time evolution. This needs `step!` (WP-7) and the compressible diagnostics (WP-11). WP-14 depends only on WP-10 (ROADMAP:166).
  - `workspace` (ROADMAP:126, CLAUDE.md:31) and the types `Incompressible`, `Compressible`, `LargeScaleDissipation`, `Output` (ROADMAP:15-22, 31) have no owning WP. `grep -n -E 'Incompressible\(|Compressible\(|LargeScaleDissipation|Output\(' docs/ROADMAP.md` matches only the API block.
- Consequence: parallel subagents will each re-implement E_kin, Z, the forcing hook or the model types. A missed projection of f̂ in a re-implemented hook changes the injected energy without any failing test.
- Hint: add the edges WP-9 → WP-6/WP-8 (or move the forcing hook into a WP), WP-8 → WP-7, WP-7 + WP-11 → WP-14, and assign the model, workspace and `Output` types to named WPs.

### E5 [major] The target API constructs the forcing without a grid, but the forcing constructor must check the support against the truncation
- Where: ROADMAP:17, 143; ADR-0007:5.
- Evidence: ROADMAP:17 `forcing = OUForcing(band(4, 6); ε = 1.0, τ_f = 0.05, seed = 1)` has no grid argument. ADR-0007:5 says "The constructor reports the mode count and rejects an empty support or one outside the Galerkin truncation. The forcing stores an index list". ROADMAP:9 says "Every WP keeps its interface compatible with it." The constructor cannot know the mode count, the index list or k_max. The units of `band(4, 6)` (integer index or physical k; on the `Lx = 4π` rectangle these differ by a factor 2) are not stated in ROADMAP:142 or ADR-0007.
- Consequence: the WP-9 acceptance "empty or out-of-truncation support rejected" cannot run at construction. The checks then move to `Simulation` (WP-13), which does not list them. On a rectangle the forced band can be off by a factor 2.
- Hint: either pass `grid` to the forcing constructors, or state that `Simulation` binds the support to the grid and runs the checks, and define the units of `band`.
- Resolution: _(author)_
