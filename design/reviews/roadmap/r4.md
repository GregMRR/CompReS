## Findings
### E42 [major] No work package owns the start-of-step injection rates that ROADMAP:154 assigns to `step!`, and no test checks them (production residual of r3 E36)
- Where: ROADMAP:154 (WP-8 text: "`step!` computes these rates at the start of each step and stores them in the workspace"); ROADMAP:143-147 (WP-7, the owner of `step!`); ROADMAP:145 ("`step!` is generic over the state and the right-hand side, so the same code advances a full grid and a one-mode test problem"); ROADMAP:80-81 (WP-8 comes before WP-7); ROADMAP:173-176 (WP-11); ADR-0009:17; ADR-0016:7.
- Evidence:
  - The instruction appears only in the WP-8 text. WP-8 runs before WP-7 (graph line 81), so `step!` does not exist when WP-8 is built.
  - `sed -n 143,147p docs/ROADMAP.md | grep -ciE 'inj|rate'` → `0`. The WP-7 text never mentions the rates. WP-7 lists ADR-0005 and ADR-0011, and the amendment is in ADR-0009 and ADR-0016. `grep -ci inj docs/adr/0005-time-stepping.md` → `0`.
  - ROADMAP:145 requires `step!` to work on a one-mode problem without a grid or forcing. This conflicts with a `step!` that computes grid-mean injection rates, unless a hook is defined, and the plan defines none.
  - The compressible rates (`⟨ρu·f⟩`, `⟨q curl f⟩`) are specified in WP-8, which comes before WP-10. WP-11 (compressible diagnostics) does not mention them: `sed -n 173,176p docs/ROADMAP.md | grep -ciE 'inj|rate'` → `0`.
  - No acceptance item tests an `inj_*` value. The two `Accept` lines that contain "inj" are the WP-9 OU test, which drives `u' = f` by hand, and the WP-13 NaN injection.
- Consequence: the WP-8 agent has no `step!` to modify. It falls back to the default diagnostic form `(state, workspace) → value` of ADR-0009:17. That form samples `u_{n+1}` with `f_n`, which is the +Δt/τ_f bias that r3 E36 measured. No test fails, so the bias reaches production `global.nc`. The compressible rates may never be implemented, because each WP can read them as another WP's task. The value written at t = 0, or after a restart before the first step, is also undefined.
- Hint: move the rule to WP-7 as a named hook (`store_injection!(workspace, state, forcing)`, a no-op without forcing) with WP-8 and WP-11 as owners of its methods. Add a blocking test: in a forcing-only run, `inj_E_kin == (E_kin(n+1) − E_kin(n))/Δt` to round-off.
