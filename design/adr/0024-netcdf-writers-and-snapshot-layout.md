# NetCDF writers, file layouts and restart checks

Date: 2026-11-19. Status: accepted.

WP-12 fixes the parts of ADR-0009 that leave the file layout and the writer interface open.

- **Writers open once, append per sample, close once.** `open_global` and `open_spectral` return an open `NCDataset`; `write_global!` and `write_spectral!` append one record and flush it to disk (`sync`), so a run that stops at its walltime leaves complete records. The caller closes the file. `write_snapshot` writes one complete file per call. `WP-13` owns the datasets and the sample counters.
- **Output selection.** `Output(; period, diagnostics = nothing)` holds the period and the names; `nothing` selects `default_diagnostics`. `selected_diagnostics(output, class, model)` resolves it to the `name => Diagnostic` pairs that the writers take.
- **GLOBAL layout.** Unlimited dimension `time`; variables `time` (`T`), `step` (`Int64`) and one `(time)` variable per diagnostic, all of float type `T` of the grid.
- **SPECTRAL layout.** Unlimited `time` and fixed `shell` (one entry per grid shell, ADR-0022). Coordinate variables `shell_k`, `shell_edge` (type `T`), `shell_count`, `shell_count_all` (`Int64`). Each diagnostic is a `(shell, time)` variable with the attribute `coordinates` set to its coordinate name (`shell_k` or `shell_edge`).
- **Snapshot layout.** The name is `snap_NNNNNN.nc`, where `NNNNNN` is the snapshot index (sample number of the FIELDS class, 0 at `t₀`), not the step. Dimensions `x`, `y`; variables `x`, `y` (grid-point coordinates), the physical fields (`ux`, `uy`, compressible `rho`), scalars `t` (`T`) and `n` (`Int64`), and `forcing_<name>` for each entry of `forcing_state`. A complex vector is stored as `(complex = 2, index)` of real parts and imaginary parts. The seed is the attribute `forcing_seed`.
- **Parameters.** `parameters(problem; run)` builds one nested table: `float_type`, `model` (with its `large_scale` and `eos` sub-tables), `grid`, `forcing` and `run` (driver settings such as scheme and `Δt`, supplied by WP-13). It holds scalar fields only; arrays and the forcing state are left out. `params.toml` is this table. Each `.nc` file gets it as global attributes, with the keys joined by `_` (`model_eos_cs`, `forcing_seed`), booleans as 0 or 1, and the attributes `output_class` and `period` (not for FIELDS). Parameters keep the float type `T`, so a Float32 run stores Float32 attributes.
- **`inj_*` at `t₀` is a plain NaN.** The variables have no `_FillValue` attribute, so NaN reads back as NaN and the test compares with `isequal`.
- **Restart.** `read_snapshot!(state, problem, workspace, path)` transforms the physical fields to spectral space, applies `truncate!`, sets `t` and `n`, and restores the forcing state. It needs no `enforce_hermitian!`, because the forward real FFT of a real field is Hermitian. It rejects a file with another grid size, forcing type, forcing seed or field set (`ArgumentError`). Reading into another float type is not supported; the files hold `T` and the state expects `T`.
- **Host copies.** Each writer copies each array to the host once per write, through `Array(...)`. `write_snapshot` and `read_snapshot!` use `workspace.physical` as the device buffer for the physical fields.
