# Simulation driver: sampling rule, files of a continued run, checks and runtime log

Date: 2026-11-19. Status: accepted.

WP-13 fixes the parts of the driver that ADR-0009, ADR-0010 and the target user API leave open. Changes:

- **Keywords and defaults.** `Simulation(grid, model; forcing = NoForcing(), scheme = RK4(), integrating_factor = true, Δt, outputs = (;), outdir, max_walltime = Inf, n_check = 10, C_stop = 1, profile = false, overwrite = false)`. `Δt` and `outdir` have no default. A class absent from `outputs` writes no file. `n_check = 10` costs 2 or 3 inverse FFTs and 3 reductions per 10 steps, below 2% of an RK4 step. Without `set_initial_condition!` the state is at rest, with `ρ = 1` in the compressible model.
- **Time from the step count.** `run!` sets `t_n = t₀ + (n − n₀)Δt` after each step, evaluated in Float64 from the step count, with `Δt` the float-type value `T(Δt)` that `step!` uses. `step!` adds `Δt` to `t` in `T`; in Float32 this drifts by about `eps(t)/Δt` per step (8% per step at `t = 100`, `Δt = 1e-4`), so the driver overwrites it.
- **Sampling rule.** Each class samples at `t₀` and at the step nearest to each multiple `jP` of its period: step `n` samples when `floor((t_n + Δt/2)/P)` exceeds its value at step `n − 1`. A tie goes to the earlier step. The multiples refer to `t = 0`, so a restart, also from an off-grid walltime snapshot, keeps the sampling times. The rule is the reset rule of `RandomPhaseForcing` (ADR-0007). The run ends at the step nearest to `t_end`, the first step with `t_n ≥ t_end − Δt/2`.
- **Order inside a step.** Step, set `t`, check (every `n_check` steps), sample, then test the walltime before the next step. At `t₀` the order is check, sample, walltime test. The check comes before the sampling, so the output files hold no record of a failed state. The diagnostics of a non-positive density evaluate `log` of a negative number: in a kernel this gives NaN, in host code a `DomainError` that would hide the message of the check.
- **Checks.** The state fields must be finite (NaN or Inf fail), the grid-point density positive (compressible model), and the CFL number of WP-13 at most `C_stop`. `c` is the maximum of `c_s(ρ)` over the grid points, and the CFL maximum runs over the grid points. On a failure, `run!` writes a snapshot and throws an `ErrorException`. The non-positive-density check closes the BACKLOG item "Guard against a non-positive density".
- **Growth-factor check.** With the integrating factor, the constructor computes the largest backward propagation `τ` of the stage combinations (`Δt/2` for SSPRK3, 0 for the other schemes) and the largest linear rate `σ` over all grid modes. It rejects the combination when `exp(στ)` overflows `T`. All grid modes count: the truncated modes hold zero, and `0·Inf` is NaN. This closes the BACKLOG item "Check the SSPRK3 integrating-factor growth factor".
- **Walltime.** The clock starts at the call of `run!`. A walltime stop writes a snapshot and returns normally. Neither a walltime stop nor a failed check writes a second snapshot of a step that FIELDS has just sampled, so `max_walltime = 0` gives exactly one snapshot, `snap_000000.nc`.
- **Snapshot index.** The snapshot index counts the FIELDS samples, walltime snapshots and failure snapshots of a run. `write_snapshot` stores it as the attribute `snapshot_index` (amends ADR-0024); `restart!` reads it and continues the count. Every run segment samples FIELDS at `t₀`, so a restart writes the restored state again under the next index.
- **New run or continued run.** `set_initial_condition!` marks a new run: `run!` creates the files. A new run throws an `ArgumentError` when `outdir` holds `global.nc`, `spectral.nc`, `run.log` or a snapshot, unless `overwrite = true`, which deletes them. This guards the output of a long run against a rerun of its script. `restart!`, and every `run!` after the first, continue the run: `global.nc` and `spectral.nc` keep the records of steps before `n₀` and drop the rest, so the time axis stays monotonic after a restart from an older snapshot. The driver reads the kept records, recreates the file with the current parameters and writes them back. A continued run must select the same diagnostics. Snapshots of later indices stay until the run overwrites them.
- **Injection rates at `t₀`.** `run!` empties the stored injection rates at the start of every segment, so the `t₀` sample holds NaN also after a previous `run!` on the same `Simulation` (ADR-0019).
- **Runtime log.** `run.log` gets per segment a header (start time, model, grid, float type, backend, threads, driver settings), one progress line per FIELDS sample (`t`, `n`, last CFL number, wall time), a stop line and the TimerOutputs table. The driver rewrites the table in place after each progress line, so the file always ends with the current table. The table times `step`, `check`, `FIELDS`, and `GLOBAL` and `SPECTRAL` with one entry per diagnostic; a class's time minus its diagnostics is its file output. On a GPU, the driver synchronises the device at the end of each step, so `step` holds the device time.
- **Profile mode.** `profile = true` gives the `TimeStepper` the run's `TimerOutput`. `step!` then times `update_forcing!`, `record_injection!`, `rhs!`, `linear terms` and `stage combination` (the stage combinations with the propagator), with a device synchronisation before and after each. The macro `@profiled` compiles to the bare call when the timer is `nothing`. Per-FFT timings are not part of it (BACKLOG).
- **Driver settings in the files.** The `run` table of `params.toml` and of the NetCDF attributes holds `scheme`, `integrating_factor`, `Δt`, `n_check`, `C_stop`, `max_walltime`, `profile` and `<CLASS>_period`. `Δt` and `C_stop` have the float type `T`; `max_walltime` and the periods are Float64, as the `period` attribute of ADR-0024, because they set wall-clock and sampling times, not physics.
